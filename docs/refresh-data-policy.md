# Refresh Time Data Policy

FC Help의 갱신시간 데이터는 `refresh_reports`(FC Help 유저 제보)와
`refresh_reference_times`(초기 참고값)를 분리해서 관리한다.

## 표시 기준

- FC Help에서 말하는 갱신시간은 **2시간 거래량 갱신 기준 시각**이다.
- 기준가·상한가·하한가는 기준 시각 이후 약 0~20분 사이에 변동될 수 있다.
- 가격이 실제로 바뀐 시각을 고정 갱신시간으로 저장하지 않는다.

## 허용하는 초기 참고값

다음 중 하나에 해당하고 출처 URL과 게시 시각을 남길 수 있는 값만 사용한다.

1. FC Help가 직접 관측한 값
2. FC Help 유저가 제보한 값
3. 개별 사실 확인에 사용하는 공개 커뮤니티 자료(출처 URL 필수)
4. 명시적으로 재사용이 허용된 공개 데이터/API

선수명·시즌·SPID 등 게임 메타데이터는 NEXON Open API를 기준으로 맞춘다.

## 사용하지 않는 방식

- 경쟁 서비스의 전체 DB/API를 허가 없이 복제
- 원 작성자의 재사용 허가가 확인되지 않은 게시물 표를 통째로 seed
- 제3자 사이트의 전체 DB/표를 고빈도로 미러링하거나 사실상 복제하는 수집
- 로그인/봇 차단/접근 제한을 우회한 수집
- 출처를 확인할 수 없는 표를 사실상 확정값으로 등록
- 실제 가격 변동 시각을 고정 갱신 기준값으로 저장

## confidence

### community_reference

출처가 표시된 공개 참고값이다.
FC Help 자체 반복 검증 전에는 확정값으로 표현하지 않는다.

### estimated

SPID 순서나 인접 카드 등으로 계산한 추정값이다.
화면에서 반드시 추정값임을 표시하며 알림의 확정 기준으로 취급하지 않는다.

### verified

다음 중 하나를 만족한 값만 사용한다.

- FC Help에서 서로 다른 2회차 이상 같은 거래량 갱신 시각을 직접 확인
- 신뢰 가능한 독립 관측과 FC Help 유저 제보가 같은 값을 가리키고 운영자가 확인

## 유저 제보와 충돌할 때

- 참고값과 같은 제보는 확인 근거로 누적한다.
- 참고값과 다른 단일 제보만으로 기존 참고값을 덮어쓰지 않는다.
- 같은 다른 값으로 2건 이상 제보가 모이면 화면 계산에서는 유저 제보를 우선한다.
- 충돌 상태는 숨기지 않고 확인 중으로 표시한다.

## 출처 관리

각 참고값은 가능한 범위에서 다음 정보를 유지한다.

- `source_name`
- `source_url`
- `source_published_at`
- `confidence`
- `note`

원 출처가 삭제되거나 오류가 확인되면 해당 참고값을 재검토한다.

## 초기 운영용 공개 웹 수집

초기 운영 단계에서는 로그인 없이 일반 브라우저에서 공개되는 페이지의 갱신시간 사실 정보를 제한적으로 수집할 수 있다.

현재 자동 수집기는 운영자가 코드에 고정한 공개 페이지 allowlist만 대상으로 하며, 임의 URL 입력은 받지 않는다. 2026-10-13부터 주요 10개 시즌과 구시즌 순환 5개(총 15개)만 하루 1회 확인한다. 수집 성공 여부를 검사하고, 응답 실패·접근 제한이 생긴 출처의 기록을 임의로 만들어내지 않는다.

- 범위로 공개된 값은 `refresh_observations`에 range로 그대로 저장한다.
- 정확한 한 시각으로 공개된 값만 exact observation으로 저장한다.
- range 값의 중앙값 등을 임의로 계산해 exact 값으로 만들지 않는다.
- exact 공개값 1건은 `community_reference`까지만 사용할 수 있다.
- 서로 다른 독립 근거 2개 이상이 같은 exact 값을 가리킬 때만 `verified`로 승격한다.
- 같은 웹 도메인의 여러 페이지나 수집 경로는 독립 근거 여러 개로 세지 않고 하나의 외부 출처로 취급한다.
- 외부 출처가 `estimated`로 표시한 exact 값은 자동 `verified` 승격 근거에서 제외한다.
- 선수명·시즌은 수집 후 NEXON 공식 메타데이터와 1:1로 매칭될 때만 SPID를 자동 연결한다.
- 후보가 둘 이상이거나 일치하지 않으면 추측해서 연결하지 않는다.
- 로그인, CAPTCHA, 봇 차단, 접근 제한을 우회해서 수집하지 않는다.
- 출처 URL, 관측 범위, 관측 횟수, 최근 관측일을 가능한 범위에서 남긴다.
- 출처의 이용조건, robots 정책 또는 공개 상태가 바뀌어 자동 수집이 부적절해지면 해당 소스를 allowlist에서 제거한다.
- 동일 사이트 전체 데이터를 복제하기 위한 재귀 탐색·페이지 열거·고빈도 병렬 요청은 하지 않는다.

## 확장 원칙

전체 선수 수를 채우는 것보다 실제 이용자가 찾는 최신/인기 시즌을 우선한다.
다만 원 출처의 재사용 허가가 불분명한 전체 표는 그대로 가져오지 않는다.
대량 seed는 원 작성자나 데이터 제공자가 재사용을 명시적으로 허용한 경우에만 진행한다.

2026-10-11에 재사용 허가가 확인되지 않은 25TOTS 전체표 bootstrap은 production reference에서 제거했다.
현재 bulk reference seed는 원 작성자가 재사용을 명시적으로 허용한 자료만 사용한다.
FC Help 자체 제보/관측이 쌓이면 그 값을 우선하고 이후 검증 상태를 갱신한다.


## 자동 수집 대상

초기 운영용 일일 자동 수집은 로그인 없이 공개되는 페이지 중 실제 관측 데이터가 확인된 최신·주요 시즌을 우선한다. 현재 일일 대상은 26FSL, 26TOTS, 25UCL, TK, PTG, WG, WS, UC, 25DP, 22UCL, SPT, 26HR, 26TOTY, 25FSL, 25TOTS이며, 이미 확보한 레거시 관측 데이터는 DB에 유지한다. 고정된 공개 커뮤니티 참고 페이지에서 읽은 값도 `scraped_public` 관측으로만 저장하며 단독으로 `verified` 처리하지 않는다.

페이지가 HTTP 200이어도 관측 카드가 0장이면 빈 상태 그대로 유지하며 임의 값을 생성하지 않는다. 수집 후에는 NEXON Open API의 선수·시즌 메타데이터로 SPID를 보수적으로 매핑하고, 유일하게 식별되는 카드만 연결한다.


## 2026-10-13 운영 보완

- 검색 화면의 관측값은 전체 DB 앞 500개가 아니라 실제 검색한 선수 SPID와 이름을 기준으로 조회한다.
- 선수 상세에서 전체 참고 근거와 개별 원문 링크를 펼쳐볼 수 있다.
- 25UCL 공개 커뮤니티 참고값 중 20개 개별 사실값만 별도 수집했고, `estimated`(미검증)로 유지한다. 이 값은 자동 `verified` 승격 근거가 아니다.
- 출처 표시만으로 대량 데이터 재배포 권한이 생기는 것은 아니므로 원 게시글 전체표 자동 복제는 확대하지 않는다.
